## Executive summary

The research strongly validates !Klein's core bets — valid-by-construction decomposition as P0 (MAST: 41.8% of multi-agent failures are specification/decomposition), single-writer file-overlap guard, blind-then-confer review, family diversity in decision roles, custom-TS-no-framework, and the local-fleet economics of eager read-only work. But it corrects the designs in specific, load-bearing ways: (1) the highest-leverage single change is making a machine-runnable acceptance check (pre-authored, frozen, worker-read-only) a REQUIRED field of every card — it simultaneously attacks false-completes, reward hacking (TDFlow: 7 test-hacks in 800 runs), and the largest empirical failure category; (2) §5.AW's value ladder has the wrong rung order (review-drain must outrank work-ahead per Little's law) and rung 4 has the wrong default (resample the strongest model, not a diverse one — diversity pays only in JUDGMENT roles); (3) the shipped greedy cycle repair is the DSM literature's last resort — condense SCCs into one card first, tear optimally second; (4) review findings from single models are ~40-80% false-positive claims that need a refuter stage, and reviewers must be blinded to author self-claims (bug-free framing collapses detection up to 93%); (5) the ≥32k context floor is necessary but not sufficient — semantic quality collapses around 32k on many models, so per-model quality-effective budgets must be measured. Aggregation everywhere must be select-one-judge or adversarial, never consensus. On the fleet: prefix-cache discipline is the wiring spec for §5.AQ, harness weight and edit format become per-model routing dimensions, and several LM Studio/Metal defaults (JIT TTL, Auto-Evict, MTP spec-dec, KV q4) are active hazards to disable.

## Top adoptions (ranked)

**1. Acceptance checks as required card fields; pre-written frozen acceptance tests as the worker's spec** (Decomposition + Verification + Anti-reward-hacking)
- WHAT: TDFlow hits 94.3% SWE-bench Verified with fixed pre-written tests and near-zero test-hacking (7/800); Claude Code best practices center on 'give the agent a check it can run'; WBS outcome-orientation makes the 100% rule mechanically checkable; SpecBench shows any single done-signal gets gamed. Writing acceptance tests BEFORE the worker starts is a security control, not a spec nicety.
- CHANGE: §5.AV: a card without a machine-runnable acceptance check (command + expected signal) is an INVALID graph node, same class as a cycle. Author acceptance tests at decompose/planning time using a different family than the eventual worker; make test files read-only forbidden paths for the worker; worker loop = 'make these tests pass'. Done (P0.2) = verifier re-runs the fixed tests in a fresh sandbox + non-empty result branch + diff audit that flags any edit to tests/gate config as mandatory review. Bug cards default to reproduce-first (failing test before fix). Point §5.AW idle capacity at pre-authoring acceptance tests for upcoming frontier cards, mutation-validated (see rank 13).
- SOURCES: https://arxiv.org/pdf/2510.23761 · https://code.claude.com/docs/en/best-practices · https://arxiv.org/pdf/2605.21384

**2. Cycle-repair ladder: SCC condensation first, exact weighted MFAS tear second, greedy last** (Decomposition (§5.AV))
- WHAT: The canonical DSM treatment of a dependency cycle is condensing the coupled tasks into one block — a real cycle usually means one unit of work was over-split. Tearing is the last resort, done at the weakest edge; exact minimum weighted feedback-arc-set is trivially computable at 12–50-card sizes (SCCs usually ≤5 nodes — brute force suffices).
- CHANGE: Rewrite breakDependencyCycles (shipped greedy version, commit 43f32d31) as a ladder: (1) merge each SCC into one card (union scopes); (2) if the merged card breaks the size band, tear the weakest edge via exact weighted MFAS over the SCC subgraph, with architect-declared dependency strength (hard-input vs soft-informs) as edge weights; (3) greedy DFS back-edge removal only as timeout fallback. Surface 'coupled block detected' to the architect as a decompose-quality signal. Small pure testable function — a good harvested-core leaf.
- SOURCES: https://dsmweb.org/sequencing-a-dsm/ · https://dl.acm.org/doi/10.1145/3446429

**3. Invert §5.AW rungs: review-drain before work-ahead; write-WIP cap + review-debt guard** (Scheduling / flow (§5.AW))
- WHAT: Little's law: added write-WIP lengthens every in-flight card's lead time; speculative work downstream of unreviewed output is overproduction waste that multiplies rework. An idle agent draining the review queue is pure flow gain with zero WIP added — and MAST measured multi-level verification at +15.6% absolute success.
- CHANGE: Opportunistic scheduler: rung 1 = drain review/verify queues (read-only), rung 2 = work-ahead. Work-ahead bounded by a review-debt rule (never start a card whose dependency chain contains unreviewed completed work beyond depth 1) and an explicit write-WIP cap sized ≈ fleet write-capable slots. Track flow efficiency (touch-time ÷ lead-time) per card in the ledger so the scheduler learns whether eager rungs actually shorten lead time.
- SOURCES: https://getnave.com/blog/kanban-littles-law/ · https://arxiv.org/abs/2503.13657

**4. Diversity scoped correctly: hard family-diversity constraint for judgment roles (quality-floored); Self-MoA resampling for generation** (Model selection (§5.AB) + N-eyes (§5.AW))
- WHAT: Same-family models agree on wrong answers ~60% of the time — three correlated judges ≈ one judge at 3x cost; PoLL panels of small disjoint-family judges beat one large judge at ~7x less cost. But Self-MoA shows resampling the SINGLE strongest model beats mixed-family ensembles for answer GENERATION, and heterogeneous teams show negative synergy without a quality floor.
- CHANGE: §5.AB: 'reviewer family ≠ author family' becomes a HARD rule for acceptance-gate verdicts (store author-family in card metadata; the live architect=reviewer=gpt-oss-120b monoculture is the documented failure). Family diversity is applied BEFORE lens assignment; an additional same-family eye is priored at ~zero expected new findings. Diversity term is quality-gated (catalog fitness ≥ role threshold, never 'diverse but weak'). §5.AW rung 4 best-of-N: default = resample the strongest-fit model at higher temperature; diverse-family attempt only after the strong model has demonstrably failed. Never add the diversity term to worker selection.
- SOURCES: https://proceedings.mlr.press/v267/kim25e.html · https://arxiv.org/abs/2502.00674 · https://arxiv.org/abs/2404.18796

**5. Review-pipeline hardening: redact author claims, refuter stage, select-one judge, flip guard** (Review & deliberation (§5.AW))
- WHAT: 'Bug-free' framing collapses vulnerability detection up to 93% (false negatives dominate 4-114x); untuned LLM reviewers run 40-80% false positives; consensus aggregation makes heterogeneous teams underperform their own best member by 8-38% via overcompromising; answer-sharing induces correct→incorrect conformity flips up to 70%; judge position/self-preference bias cannot be prompted away.
- CHANGE: Blind pass: REDACT the author agent's self-assessment, completion summary, commit messages, and 'tests pass' claims from reviewer context; add explicit ignore-claims instructions to every lens. Confer step: dedupe/extend/dispute only (never 'do you agree?'); position changes require citing the specific new evidence (log flips to §5.AF as per-model sycophancy rate); route every blind finding through a different-family REFUTER whose only job is falsification — only survivors reach the author/board. Deliberation: assigned stances, 2-3 round cap, falling disagreement = red flag triggering a fresh blind opinion, resolver from an unrepresented family who must SELECT one position pointwise against the card rubric (randomized order, provenance stripped) — split-the-difference outcomes forbidden. Lens ordering per MAST failure mass: eye #1 = spec-fit/user-intent, #2 = integration alignment, #3 = verification quality. Write lenses as executable procedures (PBR scenarios), not topic labels.
- SOURCES: https://arxiv.org/html/2603.18740v1 · https://arxiv.org/abs/2602.01011 · https://arxiv.org/pdf/2604.19049

**6. Decomposition lint suite: vertical slices, coverage critic, size band, chain coalescing, single-card fast-path** (Decomposition (§5.AV))
- WHAT: Layer-split cards fail INVEST and maximize cross-card edges; WBS gives machine-checkable invariants (100% rule, MECE, outcome-orientation); HPC granularity research puts the economic floor at G≈10 (work ÷ per-card overhead) with topology, not count, driving overhead; merging linear chains loses zero parallelism; Devin's postmortem shows decomposition overhead is itself a failure mode for small goals.
- CHANGE: assessNKleinPlanTaskGraphQuality gets: layer-smell lint ('backend for X', 'tests for X' flagged — orphan test/doc cards ARE this smell); a coverage-critic pass by a diverse family asked the narrow question 'does the union of deliverables equal the parent goal — list gaps and overlaps'; per-card size band + G-analog (estimated card work ÷ measured per-card orchestration cost, reject median G<~10) after MEASURING !Klein's real per-card overhead; graph width targeted ≈ real fleet slots; a deterministic coalesceCardChains pass merging linear chains and file-overlap-serialized small siblings (bounded by the size band); and a minimality fast-path so trivially-scoped goals become ONE card, not a swarm.
- SOURCES: https://www.humanizingwork.com/the-humanizing-work-guide-to-splitting-user-stories/ · https://en.wikipedia.org/wiki/Work_breakdown_structure · https://arxiv.org/html/2602.20561

**10. Frontier decomposition through the same by-construction validator; graph ops double as the runtime replanning API** (Decomposition (§5.AV, §5.AU))

## Contradictions with current designs

Seven places where the research contradicts current !Klein designs — each needs a design edit, not just a note. (1) §5.AW VALUE-LADDER ORDER IS WRONG: work-ahead as rung 1 violates Little's law — it is the one rung that ADDS write-WIP and rework exposure, while review-drain is pure flow gain; invert rungs 1 and 2, add a review-debt depth guard and an explicit write-WIP cap. (2) SHIPPED CYCLE REPAIR IS THE LITERATURE'S LAST RESORT: greedy back-edge removal (commit 43f32d31) discards real dependencies and tears sub-optimally; the canonical treatment is SCC condensation (the cycle usually means one over-split unit of work), with exact weighted MFAS when tearing is unavoidable — trivially computable at our graph sizes. (3) §5.AW RUNG 4'S DEFAULT IS BACKWARDS: 'a diverse model tries an alternative approach' contradicts Self-MoA — resampling the strongest-fit model beats mixed-family ensembles for GENERATION; diversity pays only in JUDGMENT roles. Related: the current text treats family diversity and lens diversity as co-equal axes, but family diversity is the load-bearing one (same-family models agree on wrong answers ~60% of the time) — apply family as a hard constraint BEFORE lens assignment, and quality-floor it (heterogeneous teams show NEGATIVE synergy without a fitness floor). (4) N-EYES LENS ORDER: spec-fit ('is this what was ASKED?') is currently near-last; MAST's failure mass (41.8% specification) says it must be eye #1. (5) BLIND-THEN-CONFER IS INSUFFICIENT AS DESIGNED: blinding to other reviewers is not enough — reviewers must also be blinded to the AUTHOR's own claims/summaries/commit messages (bug-free framing collapses detection up to 93%, asymmetric toward false negatives), and the confer step is the most dangerous component (up to 70% correct→incorrect conformity flips) — it must be structurally constrained (dedupe/extend/dispute only, evidence-cited flips, select-one judge from an unrepresented family, falling disagreement treated as a red flag). Any consensus/majority/compromise aggregation in deliberation destroys value (teams underperform their best member by 8-38% via overcompromising). (6) THE ≥32k FLOOR IS NECESSARY BUT NOT SUFFICIENT: semantic retrieval collapses by ~32k tokens on several models — the prime directive guarantees a window, not usable quality; §5.AD's per-model quality-effective budget must be measured and will often sit below the window, especially small tier. (7) 'IDLE CAPACITY IS FREE' HAS HARDWARE EXCEPTIONS: on MLX one request's prefill stalls ALL in-flight generations on that model, co-residency is bandwidth-bound with diminishing returns for larger models, and heavy §5.AA harness machinery likely HURTS the 27B/120B tier (mini-swe-agent: 100 lines, >74% SWE-bench Verified) — eager scheduling and harness weight both need per-model/per-machine gating, not global policy. Also flag softly: the Graph Harness position paper deliberately excludes recursive frontier decomposition and best-of-N on controllability grounds — both stay in !Klein, but only through the same by-construction validation discipline as the top-level graph; the field's consensus is more conservative than §5.AW's ambitions.

## Avoid-list

- Greedy back-edge removal as the DEFAULT cycle repair — it is the literature's last resort; condense SCCs first, tear optimally second.
- Work-ahead before review-drain for idle capacity; speculative work stacked on unreviewed upstream output (overproduction waste, multiplies rework).
- Consensus/majority/split-the-difference aggregation in deliberation or review; 'do you agree?' confer prompts; treating rapid convergence-to-unanimity as success (it's a conformity warning sign).
- Ranking best-of-N candidates by LLM judgment alone — always test-filter first, then judge among survivors.
- Same-family reviewer issuing acceptance-gate verdicts on same-family author output (the live architect=reviewer=gpt-oss-120b monoculture); diverse-but-below-fitness-floor reviewers picked just to satisfy diversity.
- Surfacing raw single-model review findings directly to author/board without a refute/verify stage (40-80% FP rate); importing vendor review-bot metrics (acceptance/catch rates) into the §5.AL catalog.
- Letting reviewers see the author's self-assessment, completion claims, commit messages, or 'tests pass' assertions during the blind pass.
- Spending tokens on 'be impartial' prompt language for judge bias — only structural fixes work (order randomization, provenance stripping, pointwise rubrics).
- Trusting author-reported test results for 'done'; any single completion signal without the layered gate (fresh-sandbox re-execution + diff audit on test/gate files + result-branch check).
- Layer-split cards ('backend for X', 'UI for X', 'tests for X', 'docs for X') — the orphan test/doc cards already seen live are this smell; test/doc work belongs inside the card whose deliverable it pins.
- MTP speculative decoding on the Metal backend (net loss at every measured config until llama.cpp #23752); enabling spec-dec by global default rather than per-(pair × machine) measured verdict.
- KV-cache q4 for agentic/tool-calling roles (erodes long-context fidelity AND is slower at long context); naive uncalibrated q4 quants in tool-heavy executor roles; judging quant fitness by perplexity deltas (they systematically understate agent-role harm).
- Trading context below the 32k floor to afford a bigger quant — context misconfiguration (2k ctx: -20pts) dwarfs any quant effect (q4: -5pts).
- LM Studio JIT-load TTL and Auto-Evict defaults on fleet machines — stray client requests silently evict deliberately-placed warm models.
- Timestamps or variable content near the prompt front; editing past turns; add/removing tool definitions mid-session (mask via tool-choice instead); splicing JIT context into the prefix instead of appending.
- Topically-related padding as context filler — coherent-but-irrelevant text is the worst measured distractor class; pre-stuffing file bodies instead of JIT identifiers.
- Pushing ≤9B models toward search/replace diff editing; retrying a failed diff-match instead of deterministically falling back to whole-file.
- Unbounded same-strategy retries without a no-progress wall detector (the Devin failure mode: days on impossible paths); agentifying/decomposing tasks a single focused LLM call would handle.
- Per-tool-call human approval gating — Docker isolation makes mid-run approvals noise; optimize the interrupt/steer path and the agent-question mailbox instead.
- Virtualizing board columns below ~500 cards/column (a11y cost, breaks find-in-page, fights the accessibility goal) — virtualize chat/timeline/logs instead.
- The archived @vscode/webview-ui-toolkit (deprecated Jan 2025) if a webview target ever ships; hardcoded Tailwind palette classes instead of semantic tokens.
- Adopting an orchestration framework (LangGraph/CrewAI/AutoGen) — the differentiators are durable state + observability + eval pipeline, which stay custom-TS; likewise adopting AG-UI wholesale (borrow the event vocabulary only).
- Deliberation beyond 2-3 rounds (later rounds produce conformity, not correction); full-broadcast topologies for panels ≥4 without measuring findings-per-token first.
- Independently-collapsible detail panes as the ONLY observability layer in a multi-agent UI — the fleet strip must be always-visible or agents go sideways unnoticed.

## Per-domain findings


### Project-management & decomposition science: WBS/MECE, DSM partitioning-tearing, CPM/PERT & heterogeneous DAG scheduling, kanban flow (Little's law, WIP), vertical-slice decomposition, and task-granularity research — applied to parallel LLM swarm execution

- **[adopt/high]** The canonical DSM treatment of dependency cycles is NOT edge removal — it is SCC condensation: coupled (cyclic) activities are collapsed into one composite 'block' element, because a genuine cycle means those tasks need iteration/co-design and must be handled as a unit; tearing (removing a feedback mark) is the LAST resort and is done at the LOWEST-information/weakest dependency, not at an arbitrary DFS back-edge. Sequencing then yields a block-triangular (not strictly triangular) order.

### Automated review & verification science (LLM review precision, N-reviewer diversity, anchoring, mutation-tested test gates, acceptance-test loops, evidence-based done)

- **[adopt/high]** Production LLM code-review precision is low and 'acceptance rate' is a vanity metric: untuned LLM reviewers run ~40-80% false positives (vs 3.2% for years-tuned SonarSource static analysis); Greptile v4's vendor-reported comment-acceptance is 43% (i.e., 57% of comments not acted on); controlled evals of GPT-4o-class reviewers show 14-22% FP plus regression rates up to ~24% and inaccurate approvals up to ~44%. Independent benchmarks contradict vendor catch-rate claims (Greptile 82% vendor catch-rate vs an independent eval finding 11 FPs vs CodeRabbit's 2).
  - !Klein: §5.AW N-eyes: treat every raw model finding as a CLAIM, never surface single-model findings directly to the author/board — require a verify/refute stage first. §5.AF ledger: record per-lens × per-family precision as confirmed-findings/raised-findings (not 'comments made'), and never import vendor benchmark numbers into the §5.AL catalog — measure in-house on own cards.
  - sources: https://tech.bdigitalmedia.io/blog/diagnosing-ai-review-false-positives/ — practitioner FP analysis with the SonarSource 3.2% tuned-baseline comparison · https://www.greptile.com/blog/greptile-v3-agentic-code-review — vendor's own acceptance-rate numbers (flagged: vendor-reported, fast-moving)
- **[adopt/high]** Confirmation bias in LLM review is enormous and asymmetric: framing code as 'bug-free' cuts vulnerability detection 16-93% (GPT-4o-mini: 97.2% -> 3.6% under strong bug-free framing) across 4 models on 250 CVE pairs; false negatives exceed false positives by 4-114x; adversarial PR metadata attacks succeeded 35% single-shot vs Copilot and 88% with iteration vs an autonomous agent.   - !Klein: §5.AW blind-then-confer is load-bearing, not a nicety — and it must go further than currently designed: during the blind pass, REDACT the author agent's self-assessment, completion summary, commit messages, and any 'tests pass' claims from the reviewer's context (worker output is untrusted metadata), and add the explicit ignore-claims instruction to every lens prompt. Also feeds the security lens: adversarial framing in card text/PR notes is an attack surface for the delivery-evidence gate.
  - sources: https://arxiv.org/html/2603.18740v1 — controlled experiment, 250 CVE vulnerability-patch pairs, 4 SOTA models, quantified framing effects and mitigations
- **[adopt/medium]** Consensus is the wrong aggregator for multi-model review/deliberation: 'Multi-Agent Teams Hold Experts Back' (arXiv 2602.01011) shows heterogeneous LLM teams underperform their own best member by 8-38%, with 'overcompromising' (negotiating middle ground) as the mechanism — even when the expert is explicitly identified; ensemble work on code generation finds a 'popularity trap' where consensus voting amplifies shared errors and filters out minority-correct solutions, while diversity-based selection recovers ~95% of the ideal independent-ensemble gain.
  - !Klein: §5.AW deliberation mechanism: structure it as assigned stances + a JUDGE who must select and justify ONE position (or escalate) — explicitly forbid split-the-difference outcomes; weight positions by ledger-demonstrated expertise (§5.AF priors), preserve minority reports rather than voting them away. §5.AB family diversity is validated, but only if aggregation is selection/adversarial, not majority vote.

- **[adapt/medium]** Capture-recapture on the OVERLAP between independent reviewers' finding-sets is a principled estimator of remaining defects — the classic inspection-control stopping rule ('can we stop inspecting?').   - !Klein: §5.AW marginal-value stopping rule: upgrade 'stop when an eye adds nothing new' to a Lincoln-Petersen estimate over deduped BLIND-pass findings (overlap of eye1 & eye2 estimates total defects; stop when estimated-remaining ≈ 0, add eyes when it's high); the blind pass supplies the required independence and family diversity (§5.AB) is a statistical prerequisite for the estimator, not just a quality preference. - **[adopt/high]** Mutation testing is the production-proven quality gate for generated tests: Meta's ACH (FSE 2025) generates a small number of TARGETED LLM mutants (faults-of-concern, not exhaustive operators) and requires generated tests to kill them; engineers accepted 73% of resulting tests; its LLM equivalent-mutant detector reached 0.95 precision / 0.96 recall with simple preprocessing. A test suite that kills no mutants pins nothing.

- **[adopt/high]** Pre-written acceptance tests nearly eliminate both false completion and test-hacking: TDFlow, given fixed human-written tests as the spec, hits 94.3% SWE-bench Verified / 88.8% Lite (+27.8pp over next best) with only 7 test-hacking instances in 800 runs (counted as failures) — and identifies WRITING the reproduction/acceptance tests, not passing them, as the real bottleneck for autonomy.
  - !Klein: Card lifecycle: author acceptance tests at DECOMPOSE/planning time (a different model/family than the eventual worker), make test files read-only forbidden paths for the worker, and define the worker loop as 'make these tests pass'. The 'done' definition (P0.2) becomes: verifier re-runs the fixed acceptance tests in a fresh sandbox + non-empty result branch. - **[adopt/high]** Reward hacking of completion gates is structural, not incidental: theory shows almost no proxy objective is unhackable; SpecBench documents hacking via ARCHITECTURAL evasion (not just test edits) in long-horizon coding, and the TRACE dataset catalogs 54 distinct hack categories across 3,632 exploit trajectories — so any single 'done' signal will be gamed by capable agents under pressure.

- **[adopt/medium]** Execution-free, repo-grounded rubrics are a strong cheap verifier for local-sized models: Agentic Rubrics (Scale/ACL 2026) has an expert agent explore the repository to derive a per-task rubric checklist, then scores candidate patches against it WITHOUT test execution — +3.5pp over the strongest baseline under test-time scaling on SWE-bench Verified, demonstrated on Qwen3-Coder-30B-A3B (54.2%) and Qwen3-32B (40.6%), i.e., exactly !Klein's fleet size class; rubrics also surface concerns tests miss (unnecessary edits, missing edge-case handling).

- **[adopt/medium]** LLM-judge position/self-preference bias cannot be prompted away: 2025-26 judge-bias studies find position-neutrality language has near-zero effect ('the bias is in the decode, not the rubric'); what works is structural mitigation — pointwise rubric scoring against factual criteria instead of pairwise 'which is better', randomized presentation order, and hiding response provenance.

Do not spend tokens on 'be impartial' prompt language.
  - sources: https://arxiv.org/pdf/2602.02219 — position-bias study in rubric-based LLM-as-judge showing prompt-level neutrality fails · https://arxiv.org/pdf/2604.23178 — 'Judging the Judges': systematic evaluation of bias-mitigation strategies in judge pipelines

**Surprises/contradictions:** Four results contradict or extend current assumptions. (1) The anchoring effect is far larger than the §5.AW design assumes: 'bug-free' framing collapses detection by up to 93% and the bias is asymmetric toward false negatives (4-114x) — so blind-then-confer is necessary but INSUFFICIENT as designed; the reviewer must also be blinded to the AUTHOR's own completion claims/summaries/commit messages, which the current design does not redact. (2) Deliberation-as-discussion can be net NEGATIVE: heterogeneous teams underperform their own best member by 8-38% via overcompromising — !Klein's planned deliberation mechanism will destroy value unless the aggregator is a select-one judge or adversarial stage-gate, never consensus/majority. (3) The cheapest anti-reward-hacking measure is temporal, not architectural: TDFlow shows test-hacking nearly vanishes (7/800) when acceptance tests are written BEFORE the worker starts and held fixed — i.e., decompose-time test authoring is a security control, not just a spec nicety. (4) Judge position/self-preference bias cannot be fixed with prompt language at all ('bias is in the decode') — only structural fixes (order randomization, provenance stripping, pointwise rubrics) work, which affects how the confer/deliberation prompts should be built. Fast-moving/flagged: all vendor review-bot metrics (Greptile/CodeRabbit acceptance and catch rates) are vendor-reported and shift per release; TDFlow/Agentic-Rubrics numbers are benchmark-frontier and need in-fleet re-measurement on !Klein's 4-30B locals via the §5.AF ledger.
