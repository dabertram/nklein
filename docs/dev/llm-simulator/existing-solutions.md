# LLM Simulator — Existing-Solutions Research (build-vs-buy input)

Researched 2026-07-10 (web agent, 19 candidates, primary-source fetches). Decision doc: `build-vs-buy.md` (pending
the failure-catalog research). Requirements baseline: todo.md §13.

## Verdict summary

**Hybrid: buy the transport, build the semantics.**

- **Adopt `@copilotkit/aimock`** (github.com/CopilotKit/aimock, MIT, TS/Node, zero runtime deps, 643★, v1.35.1
  2026-07, very active) as transport + fixture + chaos engine: real cross-process OpenAI-compatible HTTP server
  (+ Ollama/Anthropic/11 more surfaces), SSE with latency physics (ttft/tps/jitter + model timing profiles),
  tool calls incl. multi-turn `turnIndex` fixtures, chaos modes (HTTP 500, malformed-JSON-200, TCP disconnect
  mid-stream, 429 + x-ratelimit/Retry-After headers) at server/fixture/per-request granularity, record & replay
  with preserved timing, Vitest/Jest lifecycle helper, Docker/Action.
- **Build the nklein layer nobody sells** (fits the §13 product-separation plan): model-family QUIRK profiles
  (reasoning_content vs <think>-in-content, empty-content reasoning models, family-shaped malformed tool calls),
  behavioral failure GENERATORS (token/phrase loops, mid-stream stalls, truncated tool-call JSON,
  finish_reason=length too-short), a SEEDED scenario driver (seeded PRNG selects fixtures/chaos per request via
  aimock's context headers → same seed = same misbehavior sequence), and an **LM Studio `/api/v0` shim** (model
  list/load states/TTL/stats — zero coverage in any existing tool; also simulates admission-wait/JIT-load).
- **Spike (~1 day) before committing:** verify aimock's (a) reasoning_content emission on the chat surface,
  (b) indefinite-stall capability, (c) /v1/models, (d) strict fixture-miss behavior. Fallback if the spike fails:
  bespoke server modeled on dwmkerr/mock-llm (clean TS/JMESPath rules) or zerob13/mock-openai-api
  (x-mock-scenario/x-mock-error/x-mock-seed header ergonomics) — a few hundred LOC, but re-implements streaming
  physics/chaos/replay that aimock gives free.
- **Complementary tiers:** llm-d/llm-d-inference-sim (Go/Docker; best-in-class load-dependent latency, KV-cache,
  vLLM-flavored — for fleet-scale scheduling realism later) and llama.cpp + stories260K (~1MB real model, llama.cpp
  CI-proven) as a "real server, real quirks" smoke tier.

## Rejected candidates (why)

- **Microsoft Dev Proxy** (OpenAIMockResponsePlugin/LanguageModelFailurePlugin): intercepting .NET proxy; LLM mock
  REQUIRES a real local Ollama model → non-deterministic; its ~15 failure patterns are CONTENT-quality failures
  (hallucination, bias, circular reasoning…) generated by an LM — useful as a taxonomy checklist, not a CI mock.
- **WireMock/MockGPT**: LLM part is SaaS (WireMock Cloud); OSS core is Java with long-standing SSE/chunked issues
  (#460, #1972, #2987).
- **mokksy/ai-mocks**: good SSE-first design but Kotlin/JVM.
- **FakeAI** (Python): remarkable feature list (o1-style reasoning, parallel tool calls, 37+ model latency
  profiles, error injection) but 2★ one-person project — adoption risk; good DESIGN REFERENCE for our profile layer.
- **LiteLLM mock_response/mock_timeout**: single canned response per model; for testing LiteLLM apps, not simulating
  an endpoint.
- **StacklokLabs/mockllm** (stale, no tools), **kagent-dev/mockllm** (explicitly no errors/latency/reasoning),
  **patrickjm/openai-mock-api** (archived 2025-12 — its conversation-first YAML fuzzy matching is worth copying),
  **chihebnabil/openai-api-mock** (in-process nock only — but the ONLY candidate with documented seeded variance),
  **polly3d/mockai, freakynit, piyook, a-poor, Rust openai-mock** (hobby-scale), **MockServer** (Java; transport
  yes, LLM semantics DIY), **MSW/Polly.js/LangChain fakes/promptfoo echo** (in-process or record-only),
  **Hoverfly/Mountebank** (LLM-blind service virtualization).

## Gaps no existing tool covers (our layer, regardless of base)

1. LM Studio `/api/v0` surface (list/load-state/quant/ctx + chat `stats`).
2. Model-family CONTENT quirks (reasoning channel variants, family-shaped malformed tool calls).
3. Behavioral failure generators (loops, mid-stream stall with open connection, truncated tool-JSON, rabbit-holing).
4. Seeded variance ("same seed, same misbehavior sequence").
5. Fleet lifecycle realism (load/unload, admission waits, JIT-load timing).
