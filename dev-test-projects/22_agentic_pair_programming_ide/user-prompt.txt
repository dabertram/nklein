Create a dependency-linked implementation plan with roughly 85-100 cards before coding. Track knowledge debt explicitly: unclear standards, model limitations, security assumptions, privacy constraints, fixture limitations, user-trust tradeoffs, and places where expert review would be required in a real product.

Be especially careful with trust boundaries: model context, memory, tool execution, repository writes, sandbox paths, hidden tests, secret data, and human approval states must be modeled explicitly.
